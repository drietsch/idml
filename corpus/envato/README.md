# Envato corpus

61 third-party InDesign templates downloaded from Envato, used as a
real-world fidelity corpus. Big, varied, multi-page, real fonts, real
images — far rougher coverage than the synthetic `corpus/generated/`
fixtures.

## Layout

```
corpus/envato/
  *.zip                           # source packs (gitignored)
  manifest.json                   # one entry per pack
  fidelity-thresholds.json        # per-pack budgets for gated packs
  gen-manifest.py                 # rebuild manifest from zips
  unpack.sh                       # extract zip → packs/<name>/
  export-idml.sh + .jsx           # InDesign INDD → IDML
  export-pdf.sh  + .jsx           # InDesign IDML → reference PDF
  test.sh                         # top-level runner
  overrides/<pack>/               # per-pack handcrafted font sidecars
    fonts.sh                      # renderer --font-family flags
    fonts.jsx                     # InDesign font-substitution map
    notes.md                      # context, edge cases, calibration notes
  overrides/_default/             # fallback for packs without overrides
  packs/<pack>/                   # extracted artefacts (gitignored)
    template.idml                 # always
    reference.pdf                 # exported by InDesign on demand
    original-readme.txt           # cleaned-up readme from the zip
    Document fonts/               # symlink → corpus/fonts/
    .unpacked                     # sentinel
  reports/<pack>/                 # diff outputs (gitignored)
    cand-NNN.png   ref-NNN.png   heat-NNN.png
    report.json   pack.json   gate.json
  reports/summary.json            # cross-pack roll-up
```

## Quickstart

```bash
# 1. Drop pack zips into corpus/envato/.

# 2. Regenerate the manifest. Idempotent; preserves the stage / skip_reason
#    fields you've hand-curated. Picks one IDML per pack (the smallest by
#    path-depth) and parses fonts out of the readme.
python3 corpus/envato/gen-manifest.py

# 3. Run the harness. First run is slow because (a) every pack is
#    unzipped and (b) every pack's reference PDF is generated by driving
#    InDesign. Subsequent runs are cache-hit.
corpus/envato/test.sh                              # every non-skip pack
corpus/envato/test.sh ancient-building-magazine    # one pack
```

InDesign 2025 must be installed at the standard
`/Applications/Adobe InDesign 2025/` path; the export scripts drive it
via `osascript`. If you're in a CI container without InDesign, set
`IDML_ENVATO_SKIP_EXPORT=1` to render+diff against pre-existing
`packs/<name>/reference.pdf` files only.

## Manifest schema

```json
{
  "packs": [
    {
      "name": "ancient-building-magazine",
      "zip": "ancient-building-magazine-2025-10-31-23-54-32-utc.zip",
      "idml_in_zip": "Main Files/Ancient Building Magazine.idml",
      "indd_in_zip": null,
      "readme_in_zip": "Main Files/Read Me.txt",
      "declared_fonts": ["Poppins", "DM Sans", "Instrument Serif"],
      "stage": "smoke",
      "skip_reason": null
    }
  ]
}
```

`stage`:
- `smoke` — render the IDML through `paged-inspect`, diff page-by-page
  against the InDesign-exported PDF, but never fail the run on
  metrics. Smoke crashes are recorded in `reports/summary.json` and
  only fail the run if `IDML_ENVATO_STRICT_SMOKE=1`.
- `gated` — additionally apply the per-pack thresholds in
  `fidelity-thresholds.json`. A gated pack failing → non-zero exit.
- `skip` — never touched. Used for the 180-IDML `gridtastic-grid-kit`
  and any pack we explicitly want to leave out.

`indd_in_zip` is set only on packs that ship no IDML. On first unpack
for such a pack, `unpack.sh` drives InDesign to export an IDML from
the INDD before going further.

## Per-pack font sidecars

Each `overrides/<pack>/` directory tracks the substitutions for one
pack. Two files because the renderer and InDesign address fonts
differently:

- `fonts.sh` — sourced by `test.sh`. Sets `DEFAULT_FONT` (a path) and
  `FONT_FLAGS` (an array of `--font-family "X=path"` arguments for
  `paged-inspect`).
- `fonts.jsx` — `#include`'d by `export-pdf.jsx`. Defines a `SUBS`
  JavaScript object mapping declared family names to InDesign
  postscript names. Required so the InDesign-exported reference PDF
  uses the *same* fonts the renderer substitutes with — otherwise the
  diff is dominated by InDesign's missing-font fallback (typically
  [Adobe Sans], visibly different from our `Inter`).

The bundle of postscript names available to InDesign is determined by
the `Document fonts/` symlink that `unpack.sh` drops into each
`packs/<pack>/` directory, pointing at `corpus/fonts/`.

A pack without per-pack files falls back to
`overrides/_default/{fonts.sh,fonts.jsx}` — a generic mapping that
covers the most common Adobe-licensed and Google-Fonts faces seen
across the corpus.

## How a pack gets promoted to `gated`

1. Run `corpus/envato/test.sh <pack>` from a clean checkout. Note the
   per-page metrics in `reports/<pack>/report.json` and the worst-page
   roll-up in `reports/<pack>/pack.json`.
2. Inspect every page — `cand-NNN.png` vs `ref-NNN.png` (and
   `heat-NNN.png` highlights the deltas). The pack is only
   gate-worthy when the candidate looks *correct* — substituted-font
   shape drift is OK but layout breakage isn't.
3. Author `corpus/envato/overrides/<pack>/fonts.sh` and `fonts.jsx`
   if the defaults aren't right.
4. Add an entry to `fidelity-thresholds.json` with `max_mean_de`,
   `max_p99_de`, `min_ssim`, and `max_pages_with_pdf` set ~20% above
   the worst observed page.
5. Flip the pack's `stage` field in `manifest.json` from `smoke` to
   `gated`.
6. Re-run `corpus/envato/test.sh <pack>` and confirm `gate.json`
   reports `passed: true`.

Loosening a gated threshold needs a written rationale in the commit
message — exactly like the `corpus/generated/fidelity-thresholds.json`
convention.

## Improvement audit

The corpus drives a prioritised work-list of renderer improvements in
`corpus/envato/improvement-protocol.md`. Each entry is status-tracked
(`open` → `in-progress` → `fixed` → `verified`) with severity,
frequency-across-packs, evidence PNGs, root-cause hypothesis, and a
suggested fix pointing at a specific file:line. Use it as the source
of truth for "what should I work on next" after a harness run.

The protocol is consolidated from three per-tier audit files under
`corpus/envato/findings/`:

- `clean.md` — packs with worst meanΔE ≤ 5 (subtle bugs)
- `moderate.md` — 5 < meanΔE ≤ 20 (font drift + medium layout bugs)
- `rough.md` — meanΔE > 20 (missing features)

To regenerate the audit after a fix cycle:

1. Re-render the corpus: `corpus/envato/test.sh` (caches make repeat
   runs fast unless an IDML or `overrides/<pack>/fonts.jsx` changed).
2. Re-bucket packs by the new `worst_mean_de` in each
   `reports/<pack>/pack.json`. A small Python snippet to print the
   buckets lives in
   [`gen-manifest.py`](./gen-manifest.py) (adapt the strata
   thresholds).
3. Launch three `general-purpose` agents in parallel, one per
   bucket, with a prompt structured like:
   - "Audit the {clean|moderate|rough} tier. Read-only inspection
     of cand/ref/heat PNG triples + per-pack JSON. Write findings
     to `corpus/envato/findings/{tier}.md` following the schema
     below. Sort by Severity desc, Frequency desc, Effort asc.
     Aim for 8-15 findings per tier."
   - Include the per-pack metric table (cribbed from
     `summarize.py`).
   - Include the finding schema (see
     `improvement-protocol.md` for the canonical template).
4. Read each `findings/<tier>.md`, deduplicate across tiers (same
   root cause may show up in two or three buckets), and rewrite
   `improvement-protocol.md` preserving the `Status` field on any
   entry that's already `in-progress`/`fixed`/`verified`.

Entries marked `fixed` but not yet `verified` are the cue to re-run
the harness on the cited packs (the protocol lists the affected
packs in each entry's `Evidence` block) and confirm metrics
improved. Carry forward `won't-fix` entries from prior audits so
re-runs don't re-file the same observation.

## Environment

| Var                          | Default       | Purpose                                              |
| ---------------------------- | ------------- | ---------------------------------------------------- |
| `IDML_ENVATO_OUT`            | `reports/`    | Override reports directory.                          |
| `IDML_ENVATO_DPI`            | `144`         | DPI for renderer + pdftoppm.                         |
| `IDML_ENVATO_FORCE_EXPORT`   | `0`           | Re-export reference PDFs even if cached.             |
| `IDML_ENVATO_SKIP_EXPORT`    | `0`           | Skip the InDesign export step entirely.              |
| `IDML_ENVATO_STRICT_SMOKE`   | `0`           | Fail run when a smoke pack errors.                   |
| `IDML_DIFF_GATE=advisory`    | `strict`      | Match `corpus/generated/diff.sh` — never fail.       |

## Why InDesign-exported PDFs?

Many of the zips ship a PDF, but they fall into three categories:

1. **Help / instructions** — not an export of the layout.
2. **Layout export with Adobe-licensed fonts baked in** — diffs against
   our renderer (which substitutes those fonts) measure font-shape
   delta, not renderer fidelity.
3. **Layout export with the original OFL fonts baked in** — rare; would
   be usable but indistinguishable from category 2 without inspecting.

Driving InDesign locally to re-export every pack means the reference
PDF uses *the same* fonts the renderer substitutes with (via the
`overrides/<pack>/fonts.jsx` substitutions and the `Document fonts/`
symlink). That collapses the diff onto renderer behaviour rather than
font-choice mismatch.
